# 自建中继 —— 两种用法

> **普通用户只读第 1 章就够了。** 第 1 章不涉及域名、VPS、证书, 装完即用。
> 第 2 章是给想自己架一台中继的人看的, 一条命令, 照抄可跑。

- 想知道公共中继的安全边界 → [SECURITY.md](SECURITY.md) 第 7 章
- 想看接口长什么样 → [PROTOCOL.md](PROTOCOL.md) 第 8 章
- 已经在用中继, 只想让手机连上 → [REMOTE.md](REMOTE.md)

## 第 1 章 普通用户: 装完即用

### 1.1 你要做的事, 就三件

| # | 在哪 | 做什么 |
|---|---|---|
| 1 | 手机 | 装 **DSHsync**(App Gallery / 应用市场 / 侧载 APK 都可以) |
| 2 | 电脑 | 把 App 里那份「桌面端程序」发到电脑, 解压, **双击 `双击我-开始.cmd`** |
| 3 | 手机 | App 里点「**自动探测**」→ 选中「我的台式机」→ 配对 → 开始用 |

**你不需要**: 域名 ✓ VPS ✓ 公网 IP ✓ 端口映射 ✓ 注册任何账号 ✓ 懂什么是中继 ✓

> **普通用户不需要自己搞中继。** 项目方会提供一个公共中继, 桌面端程序第一次运行时会
> 自动去那里登记, 你什么都不用填。想用自己的中继, 看第 2 章。

### 1.2 第 1 步: 装 App

装好之后先别管它。

### 1.3 第 2 步: 把桌面端程序发到电脑

**在 App 里操作**(不要自己去下载):

1. 打开 App → 还没配对的那一页 → 找到「**发送桌面端程序**」/「**发送到电脑**」;
2. 选一个方式把文件发到电脑(微信文件传输助手 / U 盘 / 网盘 / 数据线都行);
3. 在电脑上**解压**, 得到一个叫 `DSH-Harmony-桌面端` 的文件夹;
4. 里面有一个 `双击我-开始.cmd`, **双击它**。

> **电脑上不需要装 Node。** 这个包里带的是单文件可执行程序(`dsh-harmony-bridge.exe`,
> 约 55 MB), 拷到任何一台 Windows 电脑上双击就能跑。
> 如果你想省磁盘, 也可以拷「源码版」, 但那台电脑需要自己装 Node.js 20 以上。

### 1.4 桌面端会打印什么

双击之后弹出的黑窗口里会打印:

```
[bridge] 手机端地址: http://192.168.1.23:8787
[bridge] 访问令牌:  <token>
[bridge] 配对二维码: ...
```

- **地址**: 手机要连的地址;
- **令牌**: 手机配对时要填的密钥(只在你自己的电脑和手机之间用);
- **二维码**: 手机扫一下就行, 不用手打。

> 这个窗口**要一直开着**, 关掉了手机就连不上了。

### 1.5 第 3 步: 配对

1. App 里点「**自动探测**」—— App 会在你的 WiFi 里找那台电脑;
2. 找到之后选中「我的台式机」;
3. 令牌那栏, 扫一下电脑上的二维码, 或者手动粘贴;
4. 点「**连接**」。

连上以后你会看到电脑上的会话列表, 点一个就能看对话, 下面输入框可以直接给电脑下指令。

### 1.6 手机和电脑不在一个 WiFi?

同一网络用上面的步骤就够了。**不在一个网络**(手机在外面 / 电脑在家里)有两种办法:

1. **用公共中继(推荐, 零配置)**: 桌面端程序会自动去公共中继登记, 手机 App 里选
   「远程」那一项, 填桌面端打印出来的远程地址即可。**你不用准备域名和证书。**
2. **自己架一个中继**: 看第 2 章。

### 1.7 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| App 里搜不到「我的台式机」 | 两台设备不在同一个 WiFi, 或者 Windows 防火墙拦了 | 连同一个 WiFi; 或者用远程连接(1.6) |
| 提示「令牌不对」 | 桌面端重装过, 令牌变了 | 重新扫一次电脑上的二维码 |
| 手机连上了但看不到会话 | 电脑上的 DSH 没有在运行 | 先把 DSH 桌面端打开 |
| 电脑窗口关了 | 桥接服务跟着关了 | 重新双击 `双击我-开始.cmd` |

## 第 2 章 想自建: 一台机器 + 一个域名 + 一条命令

> 这一章是给想自己架中继的人写的: 不想把流量交给项目方, 或者要给别人提供中继。
> 中继是**开源的**, 你可以自己审代码、自己跑。

### 2.1 你需要什么

| 东西 | 说明 | 大概多少钱 |
|---|---|---|
| 一台 Linux 机器 | 1 核 1G 就够, 官方发行版都行 | 见 2.4 |
| 一个域名 | 指向这台机器 | 几块钱一年, 或者免费(2.2) |
| 一条命令 | `tools/deploy-relay.sh`(2.5) | 0 |

**不需要**: 你的电脑一直开着 ✓ 端口映射 ✓ 云服务商的白名单 ✓

### 2.2 域名很便宜, 甚至免费

- **DuckDNS**: 免费的动态子域名, 几分钟搞定;
- **Cloudflare 免费子域**: 有账号就能建一条记录;
- **阿里云 / 腾讯云**: 几十块一年。

域名只用来签一张证书, 一年续一次, 就这一件事。

### 2.3 现在能签发 IP 证书 —— 连域名都可以不要

Let’s Encrypt 从 2025 年起支持 **IP 证书**, 所以如果你连域名都不想买, 直接让你的
中继跑在 IP 上, 签一张 IP 证书就行:

```bash
sudo certbot certonly --standalone --ip-certificate -d 203.0.113.10
```

> 部署脚本默认走域名 + Let’s Encrypt; 自签证书(没有域名、也没有 IP 证书时)也支持,
> 只是手机和桌面端要额外信任一次那个证书, 见 2.9。

### 2.4 免费机器

- **Oracle Cloud Always Free**: 永久免费的两台小机器(ARM/x86 都有), 出口带宽也够;
- **AWS / GCP / Azure**: 都有免费额度, 新账号能拿一台小机器;
- 家里的旧电脑 / NAS / 树莓派: 也行, 只要有公网 IP 或者能穿透。

### 2.5 一条命令

把仓库拉下来, 然后:

```bash
git clone https://github.com/<you>/DSHHarmony.git
cd DSHHarmony
bash tools/deploy-relay.sh --domain relay.example.com --email you@example.com
```

脚本会:

1. 检查 Node.js 20+, 没有就装;
2. 建一个普通用户 `dsh-harmony`(**中继不用 root 跑**), 把中继装到 `/opt/dsh-harmony`;
3. 申请证书(有 certbot 就用 Let’s Encrypt, 没有就自签);
4. 写 `relay.config.json`;
5. 写 systemd unit 并启动;
6. 装一个反向代理, **业务端口只开 443**, 中继的明文端口只绑 `127.0.0.1`(只有反向代理够得着);
7. 打印部署说明。

> 80 端口会为 Let's Encrypt 的续期验证开着(只这一件事用)。中继自己的明文端口永远不开。

重复执行是安全的(幂等): 更新代码之后重跑一遍就行。

可选参数:

| 参数 | 说明 |
|---|---|
| `--domain <名字>` | 中继的域名(必填) |
| `--email <地址>` | Let’s Encrypt 的到期通知邮箱 |
| `--dir <路径>` | 安装目录(默认 `/opt/dsh-harmony`) |
| `--user <名字>` | 中继以哪个用户跑(默认 `dsh-harmony`) |
| `--plain-port <端口>` | 反向代理后面的明文端口(默认 `8788`) |
| `--proxy nginx\|none` | 用 nginx 还是不用(默认 nginx) |
| `--skip-cert` | 不动现有证书 |
| `--skip-node` | 不装 Node.js |

### 2.6 部署之后的配置文件

`/opt/dsh-harmony/relay.config.json`:

```json
{
  "port": 8788,
  "host": "127.0.0.1",
  "tlsPort": 0,
  "tlsCert": "",
  "tlsKey": "",
  "publicUrl": "https://relay.example.com",
  "accountsFile": "/opt/dsh-harmony/var/accounts.json",
  "bridgePort": 8787
}
```

| 字段 | 意思 |
|---|---|
| `port` | 明文端口, 桌面端 bridge 外拨到这里(用 nginx 时只绑 127.0.0.1) |
| `host` | 监听地址; 用反向代理时写 `127.0.0.1` |
| `tlsPort` | 中继自己终止 TLS 的端口; 有 nginx 时写 `0` |
| `tlsCert` / `tlsKey` | 证书和私钥的路径; 没有就空着 |
| `publicUrl` | 手机侧要用的公开地址; 缺省就退回本机地址 |
| `accountsFile` | 账号注册表(里面是账号 id 和令牌, 不要提交到 git) |

**命令行参数覆盖配置文件** —— 临时改一个端口不用改文件:

```bash
node relay/src/cli.js --config /opt/dsh-harmony/relay.config.json --port 9000
```

### 2.7 桌面端怎么接上

桌面端 bridge 也支持配置文件。在**那台要跑 DSH 的电脑**上建
`%USERPROFILE%\.dsh-harmony-bridge\bridge.config.json`:

```json
{
  "relay": "wss://relay.example.com/bridge",
  "relayPublicUrl": "https://relay.example.com",
  "deviceName": "我的台式机"
}
```

然后照常双击 `双击我-开始.cmd`。**第一次运行会自动去中继登记**: 本机生成账号 id、
设备 id 和密钥, 中继签发令牌, 令牌存在 `%USERPROFILE%\.dsh-harmony-bridge\bridge.json`。
注册失败会直接把原因打出来(不会悄悄失败), 因为注册不上手机就找不到这台电脑。

> 配置文件里**只写地址**。账号、设备、令牌全部是本机生成的, 配置文件里写了会被直接拒绝
> —— 免得令牌被抄进一个截图或者一次备份。

### 2.8 手机怎么连

中继起来之后, 手机 App 里选「远程」, 填:

```
https://relay.example.com/<账号 id>/<设备 id>
```

完整的地址在桌面端启动后的窗口里(「phone address」那一行), 也有二维码, 扫就行。

### 2.9 自己签一个证书(没有域名)

脚本在没有 certbot 时会自签一张证书。这种情况下手机和桌面端要额外信任它:

- 桌面端: 在 `bridge.config.json` 里加一行 `"relayCa": "C:\\路径\\relay.crt"`;
- 手机: 第一次连接时弹出的对话框里核对证书的 SHA256 指纹。

### 2.10 systemd 常用命令

```bash
systemctl status dsh-harmony-relay      # 现在的状态
journalctl -u dsh-harmony-relay -f      # 实时日志
systemctl restart dsh-harmony-relay     # 重启
nginx -t                                # 检查反向代理的配置
```

### 2.11 更新

```bash
cd DSHHarmony && git pull
bash tools/deploy-relay.sh --domain relay.example.com --email you@example.com
```

账号注册表在 `/opt/dsh-harmony/var/accounts.json`, 更新不会动它。

## 附: 公共中继和自建中继的差别

| | 公共中继 | 自己架的 |
|---|---|---|
| 域名 / VPS / 证书 | 不用管 | 要准备(2.1) |
| 账号 id、令牌 | 本机自动生成 | 本机自动生成 |
| 中继能不能看见你的对话 | **现在能** —— 手机端的端到端密封还没落地, 明文过中继(见 [SECURITY.md](SECURITY.md) 第 7 章) | 看你自己那台机器 |
| 流量经过谁 | 项目方 | 只有你自己 |
| 出问题找谁 | 找项目方 | 自己看 `journalctl` |

**敏感场景建议自建。** 理由不是信任我们, 是你手里有代码: 中继是开源的, 你可以自己读、
自己审、自己跑。
